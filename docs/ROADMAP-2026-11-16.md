처음 보는 일봉 차트 한 장을 놓고 **도움 없이** 아래를 쓸 수 있다.

1. 주봉과 일봉의 방향, 근거로 삼은 고점·저점
2. 직접 고른 가격대 두세 개와 고른 이유
3. 이동평균·거래량·모멘텀이 지금 무엇을 말하는지, 서로 엇갈리는 점
4. 내 해석이 틀렸다고 볼 가격과 거기까지의 거리(% 와 ATR 배수)
5. 지금 자료로는 알 수 없는 것

이것은 "수익을 낼 수 있다"가 아니다. **차트를 근거로 계획을 세우고 복기할 수 있다**는 수준이다.

## 4. 모든 작업에 공통인 규칙

### 4.1 버전과 생성물

| 무엇을 바꿨나 | 올릴 버전 | 다시 만들 것 (이 순서로) |
|---|---|---|
| 레슨 글, 도해, 화면만 | 없음 | 없음 |
| `makeCourseQuestion()`의 문제·정답·분류, 새 유형 추가 | `COURSE_VERSION` (`src/lib/chart-course.js`) | `node tools/build-course.mjs` → `node tools/build-assessment.mjs` |
| 평가 표집 비율·경계 기준 | `ASSESSMENT_VERSION` (`src/lib/assessment.js`) | `node tools/build-assessment.mjs` |
| 탐지 규칙의 정의나 문턱 | `RULES_VERSION` | 패턴 → 교재 → 평가 전부. **이 로드맵에서는 하지 않는다** |

- 교재 버전이 바뀌면 입문 기록의 저장 키가 바뀐다. 예전 기록은 예전 키에 남고, "내 기록"과 복습에서 "이전 교재 버전"으로 보인다. 지우거나 다시 채점하지 않는다.
- 교재를 다시 만들면 평가의 연습 노출 범위가 달라지므로 **평가도 반드시 다시 만든다.** `ASSESSMENT_VERSION`도 올린다.
- 탐지기 코드를 "같이 쓰려고 함수로 뽑아내는" 작업은 정의를 바꾸는 것이 아니다. `build-patterns --check`가 바이트 단위로 통과해야 한다. 통과하지 못하면 되돌린다.

### 4.2 숫자가 적힌 곳

사례 수, 주제 수, 테스트 수가 바뀌면 아래를 같이 고친다.

- `README.md`, `DEVELOPMENT.md` 맨 위 항목
- `tests/chart-course.test.mjs`의 480·60·18·6 같은 단정
- `tests/assessment.test.mjs`의 영역 수
- 화면 문구: `src/views/home.js`, `src/main.js`의 "입문 6단계", `src/views/assessment.js`의 설명

### 4.3 새 문제 유형이 반드시 갖출 것

1. `makeCourseQuestion(ctx, i, type)` 안에서 `i` 뒤의 봉을 읽지 않는다.
2. 선택지는 **모두 실제로 정답이 될 수 있어야 한다.** 어떤 사례에서도 정답이 아닌 선택지를 넣지 않는다.
3. 상태(bucket)마다 사례가 고르게 뽑힌다. 혼재·경계·확인 대기 상태를 따로 둔다.
4. `reads`+`claims`(관찰형) 또는 `conditions`+`verdicts`(조건형)를 붙여 오답 진단이 된다.
5. `q.margin`을 넣어 평가에서 경계 사례를 고를 수 있게 한다.
6. `TASKS`에 레슨을 연결한다. 연결할 레슨이 없으면 레슨부터 만든다.
7. 테스트: 전체 사례에서 "정답은 틀린 관찰 0개, 오답은 1개 이상"(기존 `course-feedback.test.mjs`의 반복문이 새 유형도 자동으로 돈다), 미래 봉 불변, 상태별 사례 존재.

### 4.4 기록

- 최초 답과 근거는 덮어쓰지 않는다. 사후 기록은 따로 둔다.
- 새 저장 키를 만들면 `src/lib/backup.js`의 `isBackupKey`와 `VALIDATE`에 형식 검사를 넣고, 왕복·중복·손상 테스트를 넣는다.
- 글은 `textContent`로만 화면에 넣는다. `el(..., { html })`에 사용자 입력을 넣지 않는다.

### 4.5 배포 주의

`main`에 올리면 공개 사이트가 바뀐다. 교재 버전을 올린 커밋이 배포되면 사용자의 브라우저에는 새 키로 빈 진행 상태가 보인다.
그래서 **A 묶음과 D 묶음은 각각 한 번에 배포한다.** 버전을 여러 번 나눠 올리지 않는다.

### A2. 사실상 2지선다인 네 주제 (M)

**문제**: 아래 네 주제는 선택지 하나가 어떤 사례에서도 정답이 아니다.

| 주제 | 늘 오답인 선택지 |
|---|---|
| `wick` | 긴 꼬리 쪽 가격에 반드시 먼저 도달했다 |
| `atr` | ATR%의 크기는 다음 날 상승률 예측값이다 |
| `volume-rule` | 지금 자료로 판정 불가 |
| `engulf` | 내일 상승해야 오늘 조건 충족으로 판정 가능 |

**고칠 방향**: 오개념 문장은 선택지에서 빼고 힌트와 해설에 남긴다. 그 자리를 **실제로 갈리는 두 번째 관찰**로 채운다.

1. `wick` → 4지선다. 관찰 둘: 더 긴 꼬리(위/아래) × 종가의 위치(그날 고가~저가 범위의 위쪽 절반/아래쪽 절반).
   - 종가 위치 = `(close − low) / (high − low)`. 0.5와 정확히 같거나 `high === low`면 출제하지 않는다.
   - `reads`: `longer`, `closePos`. 기존 `order`(순서는 알 수 없다)는 `claims`에 넣지 않고 `reads`에만 남겨 "함께 볼 값"으로 보이게 한다.
   - `margin`: 두 관찰의 문턱까지 거리 중 작은 값(가격 대비 %).
2. `atr` → 4지선다. 관찰 둘: ATR%가 20거래일 전보다 커졌나/작아졌나 × 오늘 하루의 변동 폭이 ATR보다 큰가/작은가.
   - 오늘 변동 폭 = `max(high − low, |high − 전일 종가|, |low − 전일 종가|)`. `src/lib/oscillators.js`의 `trueRange()`를 내보내서 쓴다. 새로 계산하지 않는다.
   - "비교할 값"에 오늘 변동 폭을 더한다.
3. `volume-rule` → 4지선다 "어느 조건에서 걸렸나": 모든 조건 충족 / 거래량이 2배에 못 미침 / 종가 변화가 ±2%에 못 미침 / 직전 10거래일에 같은 조건의 날이 있었음.
   - **조건 하나만 어긋난 사례**와 모두 충족한 사례만 낸다. 둘 이상 어긋나면 출제하지 않는다.
   - 기존 상태 이름(`pass`, `near`, `price-fail`, `repeat`)을 그대로 쓰되 `near`는 "배수 1.7 이상 2 미만이고 나머지 두 조건은 충족"으로 좁힌다.
   - 조건표(`q.conditions`)는 해설 화면에 그대로 보여준다. 다만 진단은 관찰형으로 바꾼다: `read('failed', '충족하지 못한 조건', ...)`.
4. `engulf` → 4지선다: 모든 조건 충족 / 몸통 크기 조건만 미달 / 선행 추세 조건만 미달 / 둘 다 미달. 상태 `both-fail`을 새로 만든다.
5. 3번과 4번 때문에 `src/lib/course-feedback.js`의 `diagnose()`가 "조건표가 있으면 조건형"으로 보던 것을 **"`q.verdicts`가 있으면 조건형"**으로 바꾼다.
   `src/views/course-feedback.js`의 `autoCheck()`는 관찰형이어도 `q.conditions`가 있으면 조건표를 함께 그린다.
   `cross-status`는 지금 그대로 조건형이다(세 상태가 모두 실제로 나온다).
6. `q.trap`은 더 쓰는 곳이 없으면 지운다.

**테스트**

- 모든 주제에서 선택지마다 그것이 정답인 사례가 교재에 하나 이상 있다(새 테스트 하나로 18개 주제 전체를 돈다). 이 테스트가 앞으로 같은 실수를 막는다.

### A3. ADX 레슨의 설명 오류 (S)

### A5. 갭의 정의 (S)

### C1. 추세선과 채널 `trendline` (M)

담을 내용

1. 추세의 세 크기: 몇 달 이상 이어지는 큰 흐름, 그 안의 몇 주짜리 되돌림, 며칠짜리 잔물결. 어느 크기를 말하는지 먼저 밝힌다(다우 이론).
2. 상승 추세선은 **저점 둘**을 잇고, 하락 추세선은 **고점 둘**을 잇는다. 뒤 저점이 앞 저점보다 높아야 상승 추세선이다.
3. 두 점이면 어떤 선이든 그을 수 있다. **세 번째 반응이 나와야** 선으로 확인된다. 그 전에는 후보다.
4. 꼬리로 그을지 종가로 그을지에 정답은 없다. 하나를 정하고 끝까지 같은 기준을 쓴다. 이 앱은 저가와 고가로 긋는다.
5. 채널: 추세선과 나란한 선을 반대쪽 극점에 대어 폭을 본다.
6. 선이 깨졌다는 것: 장중에 넘은 것과 종가로 넘은 것을 구분한다(기존 `level` 주제와 같은 원칙).
7. 가파른 선일수록 쉽게 깨진다. 깨졌다고 추세가 반대로 돌았다는 뜻은 아니다. 기울기가 완만해졌을 수 있다.
8. 로그 축에서는 같은 선이 다르게 그려진다.

도해: `trendline-two-three`(두 점 후보와 세 번째 반응), `channel`, `trendline-break`(꼬리 이탈과 종가 이탈).

### C3. 여러 시간 단위 `timeframes` (M)

6. 조건 여러 개를 표로 묶어 보는 방식의 예로 미너비니의 추세 판정표를 소개한다. 조건의 숫자는 자료마다 다르다는 점(52주 저가 대비 25% 또는 30%)을 밝히고, 이 앱의 기준이 아니라고 쓴다.

### C4. 가격과 거래량 함께 읽기 `price-volume` (M)

1. 네 칸 표: 가격 상승·거래량 증가 / 가격 상승·거래량 감소 / 가격 하락·거래량 증가 / 가격 하락·거래량 감소. 칸마다 "확인한 사실"과 "흔한 해석"을 나눠 쓴다.
2. 돌파한 날의 거래량: 평소보다 많았는지 본다. 많았다고 유지가 보장되지는 않는다(불코우스키는 거래량이 많은 돌파에서 되돌림이 더 잦았다고 보고한다).
3. 눌릴 때의 거래량: 줄어들었는지 본다.
4. 거래량은 항상 **무엇과 비교했는지**를 붙여 말한다(직전 20봉 평균).
5. 거래량이 0이거나 거래정지였던 날, 동시호가에 몰린 거래는 일봉으로 구분되지 않는다.

도해: `price-volume-grid`.

### C5. 지수와 견줘 보기 `market-context` (S)

1. 종목이 올랐을 때 지수도 같이 올랐는지 먼저 본다.
2. 상대강도선 = 종목 ÷ 지수. 오르면 지수보다 잘 가는 중이다. 데이터 뷰어의 "상대강도"로 직접 켠다.
3. 상대강도선이 오른다고 종목이 오른다는 뜻은 아니다. 지수가 더 많이 내렸을 수도 있다.
4. 비교 지수는 시장에 맞춘다(코스피, 코스닥, S&P 500). `defaultBenchmark()`가 쓰는 규칙을 그대로 적는다.
5. 지수 자료는 이 앱에서 두 공급자 대조를 거치지 않았다는 한계를 적는다.

### C6. 국내 시장 제도가 차트에 남기는 흔적 `kr-market` (M)

**수치는 반영 전에 한국거래소 자료로 다시 확인한다.** 아래는 초안이다.

1. 가격제한폭: 하루에 전일 종가 대비 위아래 30%까지만 움직인다. 그래서 상한가로 끝난 봉은 "더 오르지 못한 것"이 아니라 "제도상 멈춘 것"이다. 미국 종목에는 이런 폭이 없다.
2. 변동성완화장치: 가격이 짧은 시간에 크게 움직이면 2분 동안 주문을 모아 한 번에 체결한다. 일봉에는 흔적이 남지 않는다.
3. 동시호가: 장 시작 전과 마감 직전에는 주문을 모아 한 가격에 체결한다. 시가와 종가가 이렇게 정해진다.
4. 수정주가: 액면분할이나 권리락이 있으면 과거 가격을 고쳐 이어 붙인다. 이 앱의 자료가 어떤 기준인지(`provenance.sourceAdjustment`)를 풀어 쓴다.
5. 거래정지: 거래가 없던 날은 봉이 없다. 날짜 간격을 확인한다.
6. 색: 국내는 상승이 빨강, 미국 화면은 흔히 초록이다.
7. 2015년 6월 이전에는 가격제한폭이 15%였다(확인 필요). 이 앱의 자료는 2015년 1월부터라 초반 몇 달은 기준이 다르다.

### C7. 계획과 위험 `plan-risk` (M)

Q1의 결정이 "넣는다"일 때만 한다. **매매 지시가 아니라 계획을 숫자로 쓰는 법**으로 쓴다.

1. 무효 가격: 내 해석이 틀렸다고 볼 가격. 사기 전에 정한다. 근거가 된 가격대(직전 저점, 돌파한 선) 바로 바깥에 둔다.
2. 거리 재기: 현재가에서 무효 가격까지 몇 %인지, ATR의 몇 배인지. ATR의 한 배 안쪽이면 평소 하루 흔들림에도 닿는다.
3. 위험 1단위(R): 무효 가격에 닿았을 때 잃는 금액. 이후의 손익을 R의 배수로 적으면 종목과 금액이 달라도 비교할 수 있다(반 타프).
4. 손익비: 지켜볼 가격까지의 거리 ÷ 무효 가격까지의 거리. 목표가는 예측이 아니라 계획을 견주는 자다.
5. 비중: 한 번에 잃어도 되는 금액을 먼저 정한다(예: 계좌의 1%). 수량 = 그 금액 ÷ (매수가 − 무효 가격). 계산 예를 하나 든다.
6. 갭: 무효 가격을 건너뛰어 시작하면 계획한 것보다 더 잃는다. 일봉 계획의 한계다.
7. 이 앱이 하지 않는 것: 어디서 사고팔지 알려주지 않는다. 계획이 좋은지 나쁜지 점수 매기지 않는다.

도해: `risk-distance`(현재가, 무효 가격, 지켜볼 가격과 ATR 눈금), `position-size`.

### C8. 승률과 손익비, 표본 `expectancy` (M)

1. 기대값 = 승률 × 평균 이익 − 패율 × 평균 손실. 승률 40%라도 이익이 손실의 두 배면 기대값은 0보다 크다. 숫자 예 둘.
2. 승률만 높고 손실이 크면 기대값이 0보다 작을 수 있다.
3. 연속 손실: 승률 50%에서도 다섯 번 연속 손실은 흔하다. 100번 중 몇 번쯤 나오는지 표로 보인다(계산식을 주석에 남긴다).
4. 표본 수: 20번의 결과로는 승률을 알 수 없다. 이 앱의 통계가 표본 수를 같이 적고 적으면 경고하는 이유.
5. 이 앱의 "과거 통계"는 **진입 시점 하나와 20거래일 뒤의 종가**만 잰다. 손절·익절·비용이 없으므로 기대값이 아니다.
6. 과거에 맞춘 규칙이 앞으로도 맞는다는 보장은 없다. 설정을 여러 개 시험하면 우연히 좋은 것이 반드시 나온다.

가상 차트의 실험(F4)과 연결한다.

### C9. 판단을 흐리는 습관 `biases` (S)

차트 읽기에서 실제로 나타나는 모습으로 쓴다. 심리학 용어는 한 번만 붙인다.

1. 내 생각에 맞는 근거만 보인다(확증 편향) → 반대 근거 칸을 먼저 채운다.
2. 결과를 알고 나면 처음부터 알았던 것 같다(사후 확신) → 처음 쓴 근거를 고치지 않고 따로 복기한다. 이 앱이 최초 답을 잠그는 이유.
3. 최근 몇 번의 결과에 끌려간다 → 표본 수를 센다.
4. 손실을 확정하기 싫어 무효 가격을 옮긴다 → 무효 가격을 미리 적는다.
5. 과거 차트에서는 모든 패턴이 또렷해 보인다 → 봉 넘기기(F2)로 오른쪽을 가리고 본다.

### D1. 추세선 `trendline` (조건형) (M)

- 보이는 구간: 최근 80봉. 극점: `pivots(view, 3)`. 오른쪽 3봉이 끝난 극점만 쓴다.
- 후보 선: 마지막 두 저점 `P1`, `P2`(10봉 이상 떨어짐, `P2.low > P1.low`)를 잇는 상승선. 조건에 맞는 저점 쌍이 없으면 고점 둘(`P2.high < P1.high`)을 잇는 하락선. 둘 다 없으면 출제하지 않는다. 둘 다 있으면 `hash.js`로 하나를 고른다.
- 선의 값: 두 점을 지나는 직선을 봉 번호로 늘려 오늘까지 계산한다.
- 조건 (상승선 기준, 하락선은 부호 반대)
  1. 두 점 사이의 모든 종가가 선 위에 있다 → 충족 / 불충족
  2. 둘째 점 뒤 4봉째부터 오늘 사이에, 저가가 선에서 ±1.5% 안으로 들어온 날이 있다(세 번째 반응) → 충족 / 아직 없음(확인 대기)
  3. 둘째 점 뒤로 오늘까지 종가가 선 아래로 끝난 날이 없다 → 충족 / 불충족
- 종합: 1이나 3이 불충족이면 불충족, 2만 대기면 확인 대기, 아니면 충족. 선택지와 `verdicts`는 `cross-status`와 같은 셋.
- 화면: `q.lines`를 기울어진 선도 받게 넓힌다(`{ from, to, valueFrom, valueTo }`). 표시 `점1`, `점2`. 세 번째 반응 날짜는 `revealMarkers`.
- 비교할 값: 두 점의 날짜와 저가, 오늘 선의 값, 오늘 종가.
- 상태: `up:pass`, `up:fail`, `up:pending`, `down:...` 여섯. `margin`: 오늘 종가와 선의 거리(%).
- 레슨: `trendline`.

### D2. 가격대의 반응 횟수 `sr-level` (관찰형) (M)

- 최근 120봉에 `supportResistance(view, { minTouches: 2 })`를 돌린다. 극점 기준 좌우 5봉은 그대로다.
- 묶음 하나를 `hash.js`로 골라 그 가격에 가로선을 긋는다.
- 관찰 둘: 반응 횟수(두 번 / 세 번 이상) × 오늘 종가의 위치(선 위 = 지지 후보 / 선 아래 = 저항 후보). 4지선다.
- 종가가 가격대(±1.5%) 안에 있으면 출제하지 않는다.
- 질문: "표시한 가격대(위아래 1.5%)에서 확인된 고점·저점은 몇 번 나왔고, 오늘 종가는 어느 쪽에 있나요?"
- 극점 표시는 제출 전에 보이지 않는다. `revealMarkers`로 제출 뒤에 날짜와 함께 보인다. "비교할 값"에도 날짜를 넣지 않는다(답이 드러난다). 가격대의 위아래 값과 종가만 넣는다.
- `supportResistance()`가 묶음에 속한 극점 번호를 돌려주지 않으므로 `points`를 결과에 더한다. 기존 반환값의 다른 칸은 바꾸지 않는다(뷰어가 쓴다).
- 레슨: `support-resistance`.

### D3. 주봉과 일봉 `mtf` (관찰형) (M)

- 이력 160봉 미만이면 출제하지 않는다.
- 주봉: `resample(그날까지, 'week')`에서 마지막 주(끝나지 않았을 수 있음)를 뺀다. 20주 평균 `w20`.
  - 주봉 상태: 마지막 주 종가 > `w20`이고 `w20`이 4주 전보다 높으면 상승, 둘 다 반대면 하락, 아니면 혼재.
- 일봉 상태: 종가 > 20일선이고 20일선이 5거래일 전보다 높으면 상승, 둘 다 반대면 하락, 아니면 혼재.
- 선택지 다섯: 주봉 상승·일봉 상승 / 주봉 상승·일봉 하락 / 주봉 하락·일봉 상승 / 주봉 하락·일봉 하락 / 주봉이나 일봉 안에서 위치와 기울기가 엇갈린다.
- `reads`: `weekly`, `daily` (값: up, down, mixed). 다섯째 선택지의 `claims`는 둘 중 혼재인 쪽만 주장한다. 이 때문에 `claims`에 "둘 중 하나가 혼재" 꼴이 필요하다 → `reads`에 셋째 관찰 `anyMixed`(예/아니오)를 두고 선택지 1~4는 `anyMixed: no`, 5는 `anyMixed: yes`만 주장하게 한다.
- 화면: 일봉 120봉(20일선), 아래에 주봉 차트(20주선, `weeklyOverlays`).
- 상태: `uu`, `ud`, `du`, `dd`, `mixed`. `margin`: 네 비교의 문턱 거리 중 최솟값.
- 레슨: `timeframes`.

### D4. 돌파한 날의 거래량과 마감 위치 `breakout-volume` (관찰형) (S)

- 대상: 오늘 종가가 직전 20봉 최고가보다 높은 날만(`level` 주제의 상태 0과 같은 조건).
- 관찰 둘: 거래량이 직전 20봉 평균의 1.5배 이상인가 × 종가가 그날 고가~저가 범위의 위쪽 3분의 1 안인가. 4지선다.
- 1.5배와 3분의 1은 이 연습의 기준이다. 탐지 규칙의 2배와 다르다는 점을 힌트에 적고, `settings.js`의 `price-volume` 표에 `ours`로 올린다.
- 거래량 비율은 `ctx.volume[i].ratio`를 쓴다.
- 레슨: `price-volume`.

### D5. 돌파 뒤 되돌림 `retest` (관찰형) (M)

- 돌파일 `b`: 오늘에서 3~15봉 전 사이에, 종가가 그날 직전 20봉 최고가 `L`보다 높게 끝난 가장 최근의 날. 그 전 5봉 안에 다른 돌파일이 없어야 한다.
- 오늘의 상태 (모두 `b+1`부터 오늘까지의 봉으로 판단)
  - `hold`: 저가가 한 번도 `L × 1.01` 아래로 오지 않았다 (되돌림 없이 유지)
  - `retest`: 저가가 `L × 1.01` 아래로 온 날이 있지만 종가는 모두 `L` 위 (되돌린 뒤 유지)
  - `fail`: 종가가 `L` 아래로 끝난 날이 있다 (돌파 가격 아래로 되돌아옴)
- 3지선다. 표시: `돌파일`, 가로선 `L`.
- 해설에는 "되돌림이 나온 것과 돌파가 실패한 것은 다르다"와 "이후에 어떻게 됐는지는 이 문제의 답이 아니다"를 쓴다.
- 레슨: `support-resistance`.

### D6. 다이버전스 `divergence` (조건형) (L)

**탐지기와 같은 계산을 쓴다.** `src/lib/patterns-oscillator.js`의 `divergence()` 안에 있는 "두 극점의 가격 비교, 지표 비교, 크기 문턱" 부분을 `src/lib/signal-conditions.js`의 순수 함수 `divergenceCondition(candles, series, i1, i2, cutoff, bullish, kind)`로 뽑아내고, 탐지기가 그 함수를 부르게 한다. 문턱은 `pattern-context.js`의 `DIVERGENCE_LIMITS`를 그대로 쓴다.
뽑아낸 뒤 `build-patterns --check`가 통과해야 한다.

- 입문에서는 RSI 강세 다이버전스와 약세 다이버전스만 낸다.
- 두 극점: `i1`은 확인된 극점(좌우 5봉), `i2`는 그 뒤의 극점 후보.
  - `i2`가 오늘에서 5봉 이상 전이고 좌우 5봉 조건을 채우면 확인됨.
  - `i2`가 오늘에서 4봉 이내이고 왼쪽 5봉보다 낮으면(강세 기준) 아직 확인 전인 후보.
- 조건 (숫자는 지금 탐지기의 값이다. 뽑아낸 함수에서 읽어 온다. 지시서의 숫자를 코드에 다시 적지 않는다)
  1. 가격: 둘째 저점이 첫째 저점보다 2% 이상 낮다 → 충족 / 불충족
  2. 지표: 둘째 저점의 RSI가 첫째보다 높고, 차이가 5 이상이다 → 충족 / 불충족
  3. 확인: 둘째 저점 뒤로 5봉이 지났다 → 충족 / 확인 대기
- 탐지기는 이웃한 두 극점의 간격이 10~60봉일 때만 본다. 사례를 고를 때 이 간격을 채운 쌍만 쓴다. 조건으로 묻지는 않고 "이번에 확인할 조건"에 적어 둔다.
- 탐지기의 "직전 신호와 30봉 이상 떨어질 것"은 중복을 줄이는 장치라 문제에 넣지 않는다.
- 화면: 가격 차트에 `저점1`, `저점2`, RSI 패널. RSI의 두 값은 "비교할 값"에 넣는다.
- 상태: `bull:pass`, `bull:fail`, `bull:pending`, `bear:...` 여섯.
- 레슨: `divergence`.

### D7. 같은 모양, 다른 자리 `candle-context` (관찰형) (M)

### D10. 교재와 평가 다시 만들기 (D0~D7과 한 묶음) (M)

1. `tools/build-course.mjs`는 지금 17번째 날마다 전 주제를 훑고, 드문 주제(`cross-status`, `volume-rule`, `engulf`)는 매일 훑는다. 새 주제 중 드문 것(`trendline`, `retest`, `breakout-volume`, `divergence`, `candle-context`)을 매일 훑는 목록에 더한다.

## F. 적용 연습

### F1. 계획 쓰기 `#/practice/plan` (L)

목적: 읽은 것을 "내 해석이 틀렸다고 볼 가격"으로 옮기는 연습. **계획을 채점하지 않는다. 계산만 해 준다.**

**사례**: 교재의 `retest`와 `breakout-volume` 사례를 그대로 쓴다. 새 자료 파일을 만들지 않는다. 평가 문항은 쓰지 않는다.
매수 쪽 계획만 다룬다(공매도는 다루지 않는다고 화면에 적는다).

**순수 함수 `src/lib/plan.js`**

- `planMetrics({ close, atr, invalid, target })` → `{ riskPct, riskAtr, rewardPct, ratio }`
  - `riskPct = (close − invalid) / close × 100`, `riskAtr = (close − invalid) / atr`, `ratio = (target − close) / (close − invalid)`
- `sizeFor({ account, riskPercent, close, invalid })` → `{ shares, amount, loss }`. 수량은 내림.
- `planOutcome(candles, i, { invalid, target }, days = 20)` → `{ first, bar, gapThrough }`
  - `i+1`부터 20봉을 차례로 본다. 저가가 `invalid` 이하인 봉과 고가가 `target` 이상인 봉 중 먼저 나온 쪽.
  - **같은 봉에서 둘 다 닿으면 `'same-bar'`**로 돌려준다. 일봉으로는 순서를 알 수 없다.
  - 시가가 `invalid`보다 아래에서 시작했으면 `gapThrough: true`.
  - 20봉이 모자라면 `'incomplete'`.
- `planRecord(previous, input, now)` → 최초 계획을 잠근다. 이미 있으면 그대로 돌려준다.

**화면 흐름**

1. 관찰 마감일까지의 차트(20일선, 60일선, 거래량, ATR 패널).
2. 입력: 근거로 삼은 관찰(8자 이상), 무효 가격, 지켜볼 가격, 근거 가격대(선택: 직전 20봉 최저가 / 돌파한 가격 / 20일선 / 직접 정함).
3. 입력하는 동안 계산값을 보여준다: 무효 가격까지 %와 ATR 배수, 손익비, "계좌 1,000만 원에서 1%만 잃기로 하면 몇 주".
4. 사실만 알리는 안내 (틀렸다고 하지 않는다)
   - 무효 가격이 종가보다 높다 → 입력 오류로 막는다.
   - 무효 가격까지 ATR의 한 배 미만 → "평소 하루 변동 폭 안쪽입니다"
   - 손익비 1 미만 → "지켜볼 가격까지의 거리가 무효 가격까지의 거리보다 짧습니다"
5. 제출하면 계획을 잠그고 이후 20봉을 공개한다. `planOutcome()`의 결과를 문장으로 보여준다.
6. 복기 칸: "계획대로 됐는지와 계획이 타당했는지는 다른 질문입니다"를 붙이고 따로 저장한다.

**기록**: 저장 키 `plan:v1` = `{ v: 1, items: { [사례]: { first: {...}, review: { note, at } } } }`. `backup.js`에 형식 검사를 더한다.
**집계**: 목표에 먼저 닿은 횟수를 "성적"으로 보여주지 않는다. 계획 수, 평균 무효 거리(ATR 배수), 같은 봉에서 둘 다 닿은 횟수만 보여준다.

**테스트**: 계산식, 같은 봉 처리, 갭 통과, 20봉 미만, 최초 계획 잠금, 백업 왕복. 공개 전 화면에 마감일 뒤의 봉이 없다는 것.

### F2. 봉 넘기기 (데이터 뷰어) (M)

## H. 교육 효과 검증

기능을 만든 것만으로 학습 효과가 검증됐다고 말하지 않는다. 아래는 확인하는 방법이다.

### H1. 익명 요약 내보내기 (M)

- "내 기록"에 "요약만 내보내기" 버튼. 파일에는 **글이 하나도 들어가지 않는다.**
- 내용: 형식 버전, 교재·평가 버전, 내보낸 날짜(시각 없이), 영역·주제·관찰별 횟수(첫 시도, 도움 없이, 맞음), 세션별 횟수(E2), 확신별 횟수(E3), 복습 횟수.
- 사례 식별자, 종목, 날짜, 근거 글, 이름은 넣지 않는다. 테스트로 확인한다.
- 받는 쪽 화면 `#/practice/class`: 요약 파일 여러 개를 고르면 이 브라우저 안에서 합쳐 표로 보여준다. 어디로도 보내지 않는다.

### H2. 시범 운영 절차 (사람이 한다)

1. 대상: 차트를 처음 보는 사람 5~10명.
2. 첫날: 사전 점검 한 세션(8문항) → 1~3단계 공부.
3. 1~2주: 나머지 단계와 복습.
4. 마지막 날: 사후 점검 두 세션. 1주 뒤: 간격을 둔 점검 한 세션.
5. 볼 것
   - 도움 없는 첫 시도 정답 수가 사전보다 늘었는가 (영역별)
   - 가장 자주 틀리는 관찰 다섯 개
   - "확실하다"고 하고 틀린 비율이 줄었는가
   - 중간에 그만둔 단계
6. 말로 묻는 것 세 가지: 어느 화면에서 막혔나, 어떤 말이 어려웠나, 문제를 외워서 풀었나.
7. 결과는 `docs/PILOT-날짜.md`에 적는다. 표본이 작으므로 "효과가 있다"가 아니라 "어디를 고칠지"를 찾는 용도다.

### H3. 문항 분석 (S, H2 뒤)

- 요약 파일을 모아 주제·상태별 정답률을 본다.
- 거의 모두 맞히거나(0.95 이상) 거의 모두 틀리는(0.2 이하) 상태를 찾는다. 앞쪽은 너무 쉽거나 답이 드러난 것, 뒤쪽은 문제 글이 잘못됐을 수 있다.
- 선택지마다 고른 횟수를 본다. 아무도 고르지 않는 오답은 선택지 구실을 못 한다.
- 이 분석을 하려면 요약에 "주제·상태·고른 선택지"별 횟수가 있어야 한다. H1의 형식에 넣는다.

## Z. 최종 기능 검토: 내 기준 점검기

**이번 로드맵에서는 구현하지 않는다. 검토 결과만 적는다.**

### 하려는 것

학습으로 정리한 기준을 미리 설정해 둔다. 종목을 넣으면 최근 차트를 읽어 그 기준을 기계적으로 적용하고,
보유 / 추가 매수 검토 / 일부 정리 / 전부 정리 중 무엇에 해당하는지와 그 이유를 보여준다.
사람의 마음이 끼어들 틈을 줄이고 확률로 판단하자는 목적이다.

### 이 앱의 원칙과 부딪치는 점

`CLAUDE.md` 첫머리에 "매매 추천 앱으로 바꾸지 않는다"가 있다. 이 기능은 그 문장과 부딪친다.
착수하려면 저장소 주인이 문장을 고쳐야 한다(Z0). 권하는 방향은 아래와 같다.

- 학습 영역(`#/learn`, `#/practice`)의 원칙은 그대로 둔다. 학습 점수에 매매 결과를 섞지 않는다.
- 점검기는 별도 영역(`#/rules`)으로 나눈다. 화면 이름은 "추천"이 아니라 **"내 기준 점검"**으로 한다.
- 결과 문구는 "사세요"가 아니라 **"내가 정한 정리 기준 2번에 해당합니다"**처럼 규칙의 판정으로 쓴다.
- 앱이 기본 매매 기준을 정해 주지 않는다. 책에 나온 체크리스트(미너비니, 와인스타인 등)는 출처를 밝힌 **예시**로만 불러올 수 있게 한다.

### 풀어야 할 문제

| 문제 | 내용 | 방향 |
|---|---|---|
| 최신 자료 | 자료가 2026-08-28에서 멈춰 있다. 사이트는 서버가 없는 정적 페이지다 | 아래 "자료 받는 길" 참고 |
| 수정주가 | 공공 시세 자료는 수정 전 가격일 수 있다. 분할이 끼면 평균선이 틀어진다 | 분할·권리락을 감지하면 판정을 멈추고 알린다 |
| 통계의 한계 | 지금 통계는 진입 뒤 20봉의 종가 변화만 잰다. 보유·추가·정리는 **나가는 규칙**이 있어야 잴 수 있다 | 진입·정리 규칙을 함께 돌리는 검증기를 새로 만든다 (Z1) |
| 살아남은 종목 | 종목 목록에 상장폐지된 회사가 없다. 과거 성과가 실제보다 좋게 나온다 | 화면에 항상 밝힌다. 가능하면 폐지 종목 자료를 구한다 |
| 과거에 맞추기 | 기준을 고쳐 가며 과거 성과를 올리면 우연에 맞춘 규칙이 된다 | 자료를 앞·뒤로 나눠, 앞에서 정한 기준을 뒤에서 한 번만 확인한다. 고친 횟수를 기록해 보여준다 |
| 비용 | 수수료, 세금, 원하는 가격에 못 사고 밀리는 손실 | 검증기에 넣는다. 세율은 바뀌므로 설정값으로 두고 확인 날짜를 적는다 |
| 일봉의 한계 | 같은 날 무효 가격과 목표에 모두 닿으면 순서를 모른다. 갭으로 무효 가격을 건너뛴다 | 불리한 쪽으로 가정한다 (F1의 `planOutcome`과 같은 규칙) |
| 표본 수 | 한 종목에서 한 규칙이 나온 횟수는 대개 수십 번이다 | 표본 수와 신뢰구간을 같이 보여주고, 일정 수 미만이면 확률을 숫자로 쓰지 않는다 |
| 법 | 공개 사이트에서 매매 조언으로 보이는 기능 | 아래 "법과 책임" 참고 |

### 자료 받는 길 (검토)

| 방법 | 장점 | 단점 |
|---|---|---|
| 저장소 자동 작업(GitHub Actions)으로 하루 한 번 받아 커밋 | 서버가 필요 없다. 지금 구조 그대로 | 비공식 공급자에 기대면 끊길 수 있다. 저장소가 날마다 커진다 |
| 공공데이터포털의 금융위원회 주식 시세 | 무료, 공식. 전일 종가 기준 | 영업일 다음 날 오후 1시 이후에 갱신된다. 인증키가 필요해 브라우저에서 직접 부를 수 없다(자동 작업의 비밀값으로 써야 한다). 수정주가 여부 확인 필요. 미국 종목 없음 |
| 증권사 공개 API | 당일 자료, 수정주가 | 계좌와 인증키가 필요하고 서버가 있어야 한다 |
| 사용자가 최근 봉을 직접 붙여 넣기 | 가장 단순하다. 외부에 기대지 않는다 | 번거롭다. 입력 오류 |

권하는 것: **종가 기준, 하루 한 번.** 장중 시세는 받지 않는다. 기계적으로 판단하자는 목적에는 하루 한 번이 오히려 맞다.

### 판정 구조 (초안)

1. **기준 묶음**: 사용자가 조건을 골라 만든다. 조건은 학습에서 쓴 계산을 그대로 쓴다(`signal-conditions.js`, `makeCourseQuestion`의 관찰).
   - 정리 기준 예: 종가가 무효 가격 아래 / 종가가 60일선 아래이고 60일선이 내려감 / 주봉 상태가 하락으로 바뀜
   - 추가 검토 기준 예: 주봉 상승·일봉 눌림 뒤 20일선 회복 / 돌파 뒤 되돌림 유지 / 추가 뒤에도 전체 위험이 한도 안
   - 보유: 정리 기준에도 추가 기준에도 해당하지 않음
2. **우선순위**: 전부 정리 > 일부 정리 > 보유 > 추가 검토. 정리 기준이 하나라도 걸리면 추가 기준은 보지 않는다.
3. **입력**: 종목, 매수가, 수량, 처음 정한 무효 가격, 계좌에서 잃어도 되는 한도.
4. **출력**: 해당하는 상태, 걸린 조건과 그 값, 걸리지 않은 조건, 같은 조건이 과거에 나왔을 때의 결과 분포(표본 수와 함께), 판정에 쓰지 못한 것(자료 날짜, 표본 부족).
5. **기록**: 판정마다 날짜와 결과를 남겨, 나중에 "기준대로 했다면"과 "실제로 한 것"을 견준다. 이 기능의 진짜 값은 여기에 있다.

### 단계

| 단계 | 내용 | 먼저 필요한 것 |
|---|---|---|
| Z0 | `CLAUDE.md` 원칙을 고칠지 결정. 공개 범위 결정(개인용으로만 쓸지) | 저장소 주인 |
| Z1 | **규칙 실험실**: 저장된 과거 자료에서 내 기준 묶음을 돌려 본다. 진입·정리 규칙, 비용, 앞·뒤 구간 나누기. 최신 자료가 없어도 만들 수 있고, 그 자체로 공부가 된다 | C7, C8, F1, D 묶음 |
| Z2 | 종가 자료 자동 갱신 | G2 |
| Z3 | 보유 종목 점검 화면과 판정 기록 | Z1, Z2 |

Z1부터 시작하는 것을 권한다. 기준이 과거 자료에서 어떤 성질을 보이는지 모르는 채로 Z3을 만들면 숫자 없는 체크리스트에 그친다.

### 법과 책임 (확인 필요)

- 검색으로 확인한 범위에서는, 대가를 받지 않고 불특정 다수에게 개별성 없는 정보를 주는 것은 유사투자자문업 신고 대상이 아니라고 금융감독원이 설명한다. 대가를 받거나 개별 상담을 하면 달라진다. 2024년 8월 시행된 개정법 기준이며 그 뒤의 변경은 확인하지 못했다.
- 이 기능은 사용자가 자기 기준을 넣고 자기 종목을 넣는 도구라 "개별성"으로 볼 여지가 있다. 공개 사이트에 올리기 전에 금융감독원 안내나 전문가에게 확인한다.
- 안전한 쪽: 무료, 광고 없음, 기준은 사용자가 작성, 결과는 "내 기준의 판정"으로 표시, 손실 가능성 고지. 처음에는 공개 사이트에 올리지 않고 로컬에서만 쓴다.
- 이 문서를 쓴 쪽은 투자 자문을 하지 않는다. 기준에 넣을 숫자를 정해 주지 않는다.
