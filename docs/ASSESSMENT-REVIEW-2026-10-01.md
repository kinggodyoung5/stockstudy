# 새 구간 평가 · 실제 사례 복습 · 기록 백업 (로드맵 5~6, 2026-10-01)

목표: 초보자가 차트의 어느 부분을 보고 왜 그렇게 읽었는지, 무엇을 아직 모르는지 더 정확히 설명하게 돕는다.
같은 차트나 정답 문장을 기억한 것과 다른 구간을 실제로 읽는 것을 기록상 구분한다.

이 문서의 기능을 만들었다고 학습 효과가 검증된 것은 아니다. 실제 학생에게 써 본 결과는 아직 없다.

## 5. 새 구간에서 다시 읽기 (`#/practice/check`)

### 같은 계산, 다른 선별

- 문제·정답·해설·관찰 진단은 입문 과정과 같은 `makeCourseQuestion()`·`diagnose()`로 만든다. 평가용 판정 계산기를 따로 두지 않았다.
- 경계 사례를 고르려고 `makeCourseQuestion()`에 `q.margin`(정답을 가른 비교가 문턱에서 얼마나 떨어져 있는지)만 더했다. 정답과 분류는 바뀌지 않았고 `chart-course.json`도 그대로다.
- 사례 선별·기록·성적표는 `src/lib/assessment.js`, 생성은 `tools/build-assessment.mjs`, 결과는 `data/assessment.json`.

### 선별 정책 (재현 가능)

- 이후 등락·수익률은 쓰지 않는다. 날짜 i의 출제 여부는 i까지의 봉, 고정 상수, 연습 노출 범위로만 정해진다.
  날짜·종목·주제로 만든 결정적 난수를 표집 비율과 비교하고, 같은 종목 안에서는 날짜 순서대로 앞의 사례를 남긴다.
- 표집 비율(`RATES`)과 경계 기준(`EDGE_LIMIT`)은 코드 상수로 고정했다. `--census`로 본 후보 수에 맞춰 정했으며 자료에서 다시 계산하지 않는다.
  경계 기준은 주제별 하위 약 10% 지점(예: 가격 대비 0.15%, 거래량 0.05배, RSI 3점)을 반올림한 값이다.
- 상태(bucket)·경계 여부마다 비율을 따로 둬 정상·경계·혼재 사례를 함께 넣었다. 문항 비율은 시장의 발생 비율이 아니다.
- 결과: **309문항, 82종목, 2015-07-08 ~ 2026-08-24, 경계 사례 68문항**.
  영역별로 가격·시간 60, 추세·가격대 32, 이동평균 73, 거래량·변동 폭 65, RSI·MACD 32, 맥락·종합 47.
  연습 노출과 겹쳐 빠진 후보 440개, 평가끼리 겹쳐 빠진 후보 68개.

### "새 구간"의 정의

- **화면 구간** = 학생에게 실제로 그려지는 봉. 입문 화면의 `history.slice(-viewBars)`, 주봉 문제의 주봉 20개(첫 주의 첫 거래일부터), 실제 비교 연습의 결과 공개 뒤 화면(확인일 앞 99봉 ~ 뒤 20봉).
- **계산용 이력** = 지표 계산에만 쓰고 화면에 안 나오는 앞쪽 봉. 겹침으로 세지 않는다.
- 평가 문항의 화면 구간은 입문 480사례와 실제 비교 연습 285쌍(570사례)의 화면 구간과 **한 봉도 겹치지 않는다**. 같은 종목의 평가 문항끼리도 겹치지 않는다.
- 날짜만 3봉 옮긴 입문 사례는 화면의 90% 넘게 같은 봉이며, 테스트에서 이런 후보가 노출 겹침으로 빠지는 것을 확인한다.
- 레슨 예시 표본(규칙당 최대 150개)과의 겹침은 문항마다 `lessonOverlap`(봉 수)으로 기록만 한다. 309문항 중 294문항이 어느 예시와 일부 겹친다. 예시 표본이 넓게 퍼져 있어 이것까지 빼면 문항을 거의 만들 수 없다.
- 데이터 뷰어·방향 예측 실험에서 무엇을 봤는지는 기록이 없다. 그래서 화면에는 "한 번도 본 적 없는 차트"가 아니라 **"이 기능의 기록상 처음 보는 구간"**이라고 쓴다.
- 이 기능 안에서 한 번 화면에 낸 문항은 `shown`에 남기고 새 문항으로 다시 내지 않는다. 남은 새 문항이 없는 영역은 세션에서 빼고 알린다.

### 도움과 평가의 구분

- 정답이 드러나는 해설은 제출 뒤에만 보인다. 시간 제한은 없다.
- 도움 두 가지(읽는 방법, 차트의 비교 값)는 언제든 열 수 있지만 연 순간 기록한다. 직접 계산 입력은 선택이다(비교 값을 열지 않으면 숫자가 없다).
- 같은 문항을 해설 뒤 다시 풀면 **재시도**로 따로 쌓고, 첫 시도는 바꾸지 않는다. 재시도는 빈 도움 상태에서 시작한다.

### 영역별 기록 (성적표)

- 여섯 영역(입문 6단계와 같은 분류)마다 첫 시도·맞음, 도움 없이, 도움 받고, 재시도, 직접 계산, 자기 점검 저장 횟수를 따로 센다.
- 관찰별(예: "종가와 20일 평균", "조건 종합 판정 (확인 대기 사례)")로 맞게 읽은 횟수를 보여준다.
- 퍼센트·합격선·"마스터" 인증은 만들지 않았다. 첫 시도가 5개 미만이면 판단하기 이르다고 표시한다.
- 이후 주가 적중률은 어디에도 쓰지 않는다.
- 오답·낮은 확신·도움 사용·자기 점검 미표시 주제는 복습 주제로 이어진다.

## 6. 실제 사례 복습과 기록 백업

### 복습 (`#/practice/review`)

- 출처: 입문 과정 기록(모든 교재 버전)과 평가 첫 시도 중 오답, 낮은 확신(반반·모르겠다), 평가에서 받은 도움, 자기 점검에서 표시하지 못한 항목.
- 같은 주제의 **다른 입문 사례**를 먼저 고른다. 이 복습에서 아직 안 쓴 사례 → 입문에서 아직 안 푼 사례 → 같은 상태 순서다. 다른 사례가 없을 때만 "원래 사례 재복습"으로 표시한다. 평가 문항은 복습에 쓰지 않는다.
- 공개 일정(고정 규칙): 처음 기록 1일 뒤 → 맞히면 1일, 3일, 7일 → 7일 간격까지 연속으로 맞히면 끝. 틀리면 곧바로 다시. 간격 계산은 기초 읽기 연습의 `recordAttempt()`를 그대로 쓴다. 기억 연구로 최적화한 간격이라고 주장하지 않는다.
- 일정은 저장하지 않고 복습 시도 목록에서 매번 계산한다. 백업을 합칠 때 시도만 합치면 일정도 같아진다.
- 복습 화면 위에 처음 기록(고른 답, 자동 확인, 확신, 도움, 처음 근거, 해설 뒤 생각)을 읽기 전용으로 보여준다. 예전 교재 버전 기록은 "다시 채점하지 않았다"고 표시한다.

### 기록 보존

| 기록 | 저장 키 | 처음 기록 | 나중 기록 |
| --- | --- | --- | --- |
| 입문 과정 | `chart-course:{교재}:{원자료}` | 답·근거·확신·자동 확인 | 해설 뒤 생각·자기 점검 |
| 새 구간 평가 | `assessment:v1` | 첫 시도·도움 | 재시도·자기 점검 |
| 실제 비교 | `real-study:v1` | 두 사례의 근거 | 복기 |
| 복습 | `review:v1` | — | 복습 시도 |
| 가져오기 충돌 | `backup-conflicts:v1` | — | 밀려난 기록 |

- 실제 비교 연습의 **최근 30쌍 제한과 저장 때마다 형식이 다른 기록을 지우던 동작을 없앴다.** 기존 기록은 지우지 않고 그대로 읽는다. 이미 지워진 기록은 되살릴 수 없으며 화면에도 그렇게 적었다.
- 입문 과정의 모든 문항에 "해설을 본 뒤의 생각"(선택)을 더했다. 체크 항목이 있는 종합 문제는 기존 자기 점검을 그대로 쓴다.
- 새 기록에는 고른 문장(`choiceText`)도 남긴다. 교재가 바뀌어 문제를 다시 열 수 없어도 무엇을 골랐는지 보인다.
- 저장 키를 새로 옮기는 이전 작업은 하지 않았다. 기존 키를 그대로 두고 새 키만 더했다.

### 백업 (`#/practice/records`)

- 형식: `{ format: "stockstudy-backup", formatVersion: 1, app, exportedAt, versions: { course, assessment, rules, sourceDigest }, counts, data: { 저장 키: 값 } }`.
  사례 식별자는 `주제|종목|날짜`. 평가의 진행 중 세션, 다른 기능의 저장값(예측 실험 등)은 넣지 않는다.
- 내보낼 때 지금 형식 검사를 통과하지 못한 저장값은 버리지 않고 `unverified`에 그대로 넣는다. 가져오기에서는 읽지 않는다.
- 가져오기 검사: 5MB 이하, JSON, 형식 이름, 형식 버전(더 새 버전은 해석하지 않음), 허용된 키, 모든 칸의 자료형·범위·글자 수, `__proto__` 같은 키. 하나라도 어긋나면 전체를 거부하고 기존 기록을 건드리지 않는다.
- 미리 보기(새로 더할 것·같은 것·합칠 것·충돌)를 본 뒤에만 저장한다. 저장 직전에 다시 계산한다.
- 병합 규칙
  - 없는 기록은 더한다. 같은 기록은 늘리지 않는다.
  - 최초 답이 서로 다르면 **먼저 제출한 쪽**을 남기고 다른 쪽은 충돌 보관함에 통째로 둔다.
  - 해설 뒤 생각·복기는 늦게 저장한 쪽을 쓰고, 밀려난 쪽도 보관함에 둔다. 최초 답은 사후 기록으로 덮어쓰지 않는다.
  - 재시도·복습 시도는 합집합. 같은 시도는 한 번만 남는다.
  - 기초 연습(누적 횟수 형식)은 더하면 두 번 셀 수 있어 마지막 시도가 늦은 쪽을 쓰고 다른 쪽은 보관한다.
- 여러 키를 한 번에 쓰다가 하나라도 실패하면(공간 부족·차단) 이번에 쓴 값을 지우고 원래 값으로 되돌린다.
- 글은 데이터로만 다루며 화면에는 `textContent`로만 넣는다.

## 검사

- 테스트 78개(기존 59 + 평가 9 + 복습·백업 10). 실제 비교 기록 보존 테스트 1개는 새 규칙에 맞게 바꿨다.
  - 미래 봉을 뒤틀거나 잘라도 그 이전 날짜의 출제 여부·정답·해설이 같다.
  - 평가 화면 구간이 연습 노출·다른 평가 문항과 겹치지 않는다. 3봉 옮긴 입문 사례는 겹침으로 빠진다.
  - 표집 비율은 상수이고 결과 값을 참조하지 않는다.
  - 도움 사용 기록, 도움 없이/받고/재시도 분리, 세션이 이미 본 문항을 다시 내지 않음.
  - 복습 일정, 다른 사례 우선, 처음 기록 보존.
  - 백업 왕복, 두 번 가져오기, 충돌 병합, 손상·미래 버전·위험한 값 거부, 저장 실패 되돌리기, 기존 형식(v1 기록·30쌍 초과·예전 버전 키) 보존.
- `node tools/build-assessment.mjs --check`로 `data/assessment.json`을 바이트 단위로 재현한다.
- 브라우저에서 평가 세션 6문항, 재시도, 성적표, 복습 1회, 가져오기(같은 백업·손상·미래 버전·실제 복원·저장 실패)를 실행했다. 1280/768/375px에서 가로 넘침이 없고 `word-break: keep-all`이 적용됨을 확인했다.

## 남은 한계

- 평가는 객관식·수치·조건 판정만 자동으로 확인한다. 서술 근거의 질은 채점하지 않는다.
- 레슨 예시·뷰어·예측 실험에서 본 구간은 제외하지 못했다. "기록상 처음"이라는 표현은 이 기능의 기록에 한정된다.
- 같은 종목의 다른 시기는 새 구간으로 본다. 종목 자체를 처음 보는 평가는 아니다(입문 과정에 85종목이 모두 있다).
- 평가 문항 수가 영역마다 32~73개라 오래 쓰면 새 문항이 바닥날 수 있다. 그때는 숨기지 않고 알린다.
- 기록은 브라우저 한 곳에만 있다. 백업 파일 보관은 사용자가 한다.
