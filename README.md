# 차트 읽는 법 — 주식 기술적 분석 학습 앱

차트 읽는 법을 배우는 **교육용** 웹앱입니다.
실시간 시세, 매매 기능, 종목 추천은 없습니다.

지표 20여 종을 설명으로 읽고, 실제 과거 차트에서 그게 어떻게 생겼는지 보고,
설정값을 직접 바꿔가며 익힙니다. 그리고 **배운 신호가 실제로 얼마나 맞았는지**를
같은 화면에서 바로 확인합니다.

> 개념을 읽고 → 실제 차트에서 찾아보고 → 설정을 바꿔보고 → 얼마나 맞았는지 확인하고 → 퀴즈로 점검한다.

마지막 두 단계가 이 앱의 특징입니다. 대부분의 교재는 "골든크로스는 상승 신호"까지만
말하고 끝납니다. 실제로 몇 번 중 몇 번 맞았는지는 알려주지 않습니다.
그 숫자를 지표 설명 바로 아래에 붙여둔 것이 이 앱입니다.

## 승률을 볼 때 반드시 같이 보는 숫자: 기준선

승률 55%가 좋은 숫자인지 아닌지는, 아무 신호 없이 샀을 때가 몇 %인지를 알아야 판단할 수 있습니다.
그 비교 대상이 기준선입니다.

같은 종목·같은 기간에서 **아무 날이나 사서 20거래일 들고 있으면 상승 비율 50.7%, 평균 +1.58%**입니다.
성과 통계 탭은 모든 신호를 이 숫자 옆에 나란히 놓습니다.

실제로 재보면 **규칙 57개 중 46개가 기준선에서 3%p 안쪽**에 머뭅니다. 중앙값은 +0.3%p입니다.
가장 크게 앞선 규칙도 +6.2%p이고, 그마저 표본 오차를 감안하면 확실하다고 말하기 어렵습니다.

이 숫자가 뜻하는 것은 **"차트 분석은 소용없다"가 아니라 "신호 하나만 보고 기계적으로 사서
20일 뒤에 파는 방식으로는 별 차이가 없다"**입니다. 실제 매매에서 결과를 더 크게 좌우하는
손절·익절 규칙, 포지션 크기, 여러 신호의 조합은 이 통계에 들어 있지 않습니다.
지표를 언제 믿고 언제 의심할지 감을 잡는 용도로 보세요.

종목 117개에는 고점 대비 크게 밀린 종목을 일부러 많이 섞었습니다. 지금 유명한 회사만 고르면
"살아남아 크게 오른 회사들"만 남아(생존 편향) 모든 신호의 통계가 실제보다 좋게 나오기 때문입니다.

### 성과는 "그 신호를 알 수 있게 된 날"부터 잽니다

판정에 뒷날 봉이 필요한 규칙이 있습니다. 예를 들어 다이버전스는 국소 저점 두 개를 비교하는데,
어떤 날이 저점인지는 **뒤로 5봉이 더 지나야** 정해집니다. 그 전에는 더 떨어질 수 있으니까요.

이때 성과를 저점 당일부터 재면 승률이 크게 부풀려집니다. "뒤 5봉보다 낮다"가 저점의 정의이므로
그 5봉은 반드시 위에 있기 때문입니다. 규칙이 스스로 만들어낸 수익을 신호의 성과로 착각하게 됩니다.
실제로 이 방식으로 재면 다이버전스 승률이 69%까지 올라갑니다. **동전 던지기로 만든 가짜 차트에서도
65%가 나옵니다.**

그래서 이 앱은 도형은 원래 지점에 그대로 그리되, **성적을 매기는 출발선만 확인일로 밉니다.**
해당하는 규칙에는 학습 탭에 "성과는 신호 N거래일 뒤부터 쟀습니다"라고 표시했습니다.
이 처리를 거치면 다이버전스 승률은 49~52%, 즉 기준선으로 돌아옵니다.

### 무작위 데이터에도 패턴은 잡힙니다

가상 차트 실험실에서 **추세도 기억도 없는 순수 난수 차트**에 같은 규칙 57개를 그대로 돌려볼 수 있습니다.
차트 50개(각 750봉)에서 **규칙 57개 중 53개가 10,139건**을 찾아냅니다.

그 데이터에는 예측할 정보가 애초에 없으므로, 승률은 모두 그 데이터의 기준선(51%) 언저리에 머뭅니다.
표본이 쌓일수록 더 그렇습니다.

| 표본 크기 | 규칙 수 | 기준선에서 벗어난 최대 폭 |
|---|---:|---:|
| 50건 미만 | 14개 | 17.7%p |
| 50~200건 | 20개 | 9.2%p |
| 200건 이상 | 19개 | 6.4%p |

표본이 적을수록 크게 튀고, 쌓일수록 기준선으로 수렴합니다. 순전한 우연이 보이는 전형적인 모습입니다.
**패턴이 눈에 보인다는 사실 자체는 그 안에 정보가 있다는 뜻이 아닙니다.**

## 실행 방법

이 앱은 ES 모듈과 `fetch`를 사용하므로 **`file://` 로 열면 동작하지 않습니다.** 로컬 서버가 필요합니다.

```bash
powershell -ExecutionPolicy Bypass -File tools\serve.ps1
```

띄운 뒤 <http://localhost:8123> 으로 접속하세요. (Node.js·Python 없이 PowerShell만으로 동작합니다)

## 기술 스택

- **빌드 도구 없음** — 순수 ES 모듈 + `lightweight-charts`(TradingView 오픈소스, `vendor/`에 직접 포함)
- 지표는 저장하지 않고 원시 OHLCV에서 **브라우저가 그때그때 계산**
- 데이터는 정적 JSON. 종목 파일은 선택할 때 그때그때 fetch

CDN을 쓰지 않으므로 오프라인·차단 환경에서도 그대로 동작합니다.

## 패턴 판정은 어떻게 이루어지나

**AI의 느낌이 아니라 코드에 적힌 정량 조건만으로 판정합니다.** 규칙은 전부
탐지 엔진 네 파일([patterns](src/lib/patterns.js) · [shape](src/lib/patterns-shape.js) · [oscillator](src/lib/patterns-oscillator.js) · [candlestick](src/lib/candlestick.js))에 있고, 앱 화면의 "판정 기준" 박스에
그대로 노출됩니다. 각 사례는 조건을 만족한 근거 수치를 함께 보여주므로 언제든 역추적할 수 있습니다.

경계가 애매한 후보는 조건을 엄격하게 잡아 아예 제외합니다 (정확한 소수 사례 > 애매한 다수 사례).
그래서 헤드앤숄더처럼 까다로운 패턴은 11종목 11년치에서 20건만 검출됩니다. 반대로 마루보즈처럼 흔한 형태는 900건 넘게 나오고, 그만큼 개별 신호의 무게는 가볍습니다.

## 데이터 갱신 절차

1. 최신 봉 이어붙이기 (평소에는 이것만):

   ```bash
   powershell -ExecutionPolicy Bypass -File tools\fetch-data.ps1 -Append
   ```

   종목을 몇 개만 새로 추가할 때는 `-Only '005490.KS,LLY'` 를 붙입니다.
   전체 재수집(`-Append` 없이)은 수집 기간이나 저장 형식을 바꿨을 때만 하세요 —
   모든 파일이 새로 쓰이면서 git 이력이 그만큼 커집니다.
2. 로컬 서버를 띄우고 <http://localhost:8123/tools/build-patterns.html> 접속 → "탐지 실행 후 저장"
3. 변경된 `data/` 를 커밋

탐지 규칙(`src/lib/`)을 고쳤을 때도 2번을 다시 실행해야 학습 탭에 반영됩니다.

## 데이터 용량

캔들 1개 ≈ 48바이트, 종목 1개(11년치) ≈ 0.13 MB. 현재 121개(종목 117 + 지수 4) = 16 MB.
탐지 결과(`data/patterns/`)는 사례를 패턴당 150건으로 상한을 둬서 종목이 늘어도 커지지 않습니다.

브라우저는 한 번에 종목 하나만 내려받고 GitHub Pages 가 gzip 으로 보내므로,
종목이 수백 개가 되어도 사용자 쪽 로딩 속도는 그대로입니다.

자세한 한계선과 대응 방안은 [docs/CAPACITY.md](docs/CAPACITY.md) 참고.

## 배포

정적 사이트라 빌드 설정이 필요 없습니다. 자세한 절차는 [tools/DEPLOY.md](tools/DEPLOY.md).

> 저장소 루트의 빈 `.nojekyll` 파일을 지우지 마세요. GitHub Pages 의 Jekyll 이
> `_` 로 시작하는 파일을 결과물에서 제외해서, 통계 탭(`_index.json`)과
> 상대강도용 지수 파일(`_KS11.json` 등)이 404 가 됩니다.
